Lobby System Architecture
매니저 역할 분리로 본 로비 화면의 동작 구조

InitManager · LobbyMapManager · LobbyCharacterManager · SettingPopupPresenter

Data LayerDataManager / MapManager / CharacterManager가 JSON·Addressable SO를 미리 로드해 캐시를 만듭니다.
Lobby LayerLobbyMapManager·LobbyCharacterManager가 캐시 데이터를 읽어 더미 프리팹을 풀링·배치·표시합니다.
UI / Scene LayerSettingPopupPresenter와 LobbyCameraController가 입력을 받아 선택값을 PlayerData·MapManager에 기록합니다.
핵심 문장: 로비는 콘텐츠를 생성하지 않습니다. 미리 캐싱된 데이터 위에 더미를 배치하고, 선택값(index·이름)만 인게임으로 넘깁니다.
캡스톤디자인(1) 로비 시스템 발표
로비 시스템 레이어 구성 책임 단위로 매니저를 나눠 데이터·표현·입력이 서로 침범하지 않도록 분리
① Data Layer (전역 캐시) DataManager · MapManager · CharacterManager · PoolManager. JSON 수치와 Addressable SO를 메모리에 올리고 풀을 준비합니다.
② Lobby Layer (씬 전용 매니저) LobbyMapManager · LobbyCharacterManager. 캐시된 데이터를 읽어 lobbyDummyMap / lobbyCharacterDummy를 풀에서 꺼내 로비 화면을 구성합니다.
③ UI · Input Layer SettingPopupPresenter · CharacterTabPresenter · LobbyCameraController. 입력을 받아 매니저에 명령을 전달하고, 선택 결과를 PlayerData·MapManager에 기록합니다.
설계 원칙

“데이터 매니저는 전역, 로비 매니저는 화면 전용”

  • Data Layer는 씬에 종속되지 않고 게임 시작 시 한 번 캐시를 채웁니다.
  • Lobby Layer는 그 캐시만 참조하므로 런타임에 Resources/Addressables 검색이 발생하지 않습니다.
  • UI Layer는 매니저의 public 메서드만 호출하고, 데이터 자체는 만지지 않습니다.
통신 방식

EventBus로 씬 전이를 알림

GameManager가 씬을 바꾸면 LobbySceneLoaded 이벤트가 Publish 됩니다. 두 로비 매니저는 이 이벤트만 듣고 자신의 더미 풀을 켜거나 꺼서, 로비 외 씬에서는 어떤 더미도 보이지 않게 합니다.

왜 이 순서인가

로비 매니저는 “이미 로드된 SO”만 읽는다

  • LobbyMapManager는 MapManager.GetMapScriptable(mapId)를 호출해 lobbyDummyMap을 얻습니다.
  • LobbyCharacterManager는 CharacterManager.GetCharacterMap()으로 모든 CharacterIdentity를 받습니다.
  • 따라서 두 데이터 매니저의 로드가 끝난 뒤에야 로비 매니저를 초기화할 수 있습니다.
// InitManager.InitAsync() dataManager.Init(); await mapManager.LoadMapConfigAsync(); await characterManager.LoadCharacterIdentitiesAsync(); // ↑ 캐시 완성 → ↓ 로비 매니저 초기화 가능 await lobbyMapManager.InitLobbyAsync(); await lobbyCharacterManager.InitLobbyAsync(); IsLoaded = true;

책임 1 — 더미 풀링 & 배치

CacheDummyRefs → BuildLobbyMapsAsync

  • CacheDummyRefs(): DataManager의 맵 개수만큼 돌며 각 MapScriptable의 lobbyDummyMap 레퍼런스를 모읍니다.
  • BuildLobbyMapsAsync(): PoolManager.lobbyMapPool에서 더미를 꺼내 (0, i × yOffset, 0) 위치에 배치 합니다.
  • 풀에 없으면 GetObjectAsync로 Addressable에서 비동기 로드 후 풀에 등록합니다.
책임 2 — 잠금 시각화 & 갱신

ApplyVisual + MapCleared 구독

  • 해금된 인덱스(_firstUnlockedMapIndex) 이후의 더미는 lockedAlpha로 반투명 처리합니다.
  • 원래 색상은 _originalBaseColors / _originalUrpColors 딕셔너리에 저장해 두고 복구할 때 사용합니다.
  • MapCleared 이벤트를 받으면 다음 맵을 해금하고, 해당 더미에 대해 ApplyVisual(locked: false)를 호출합니다.
책임 3 — 카메라 셋업 & 선택 확정

SetLobbyCamera / SelectFocusedMap

  • LobbySceneLoaded 이벤트에서 LobbyCameraController를 찾아 더미 수·yOffset·해금 인덱스를 넘겨 Setup 합니다.
  • F3 / 선택 입력이 들어오면 SelectFocusedMap()이 잠금 검사를 한 뒤 MapManager.SetCurrentMapIndex()를 호출하고 InGame 씬으로 전환합니다.
// LobbyMapManager.SelectFocusedMap() int index = FocusedMapIndex; if (index > _firstUnlockedMapIndex) return; // 잠금 컷 _mapManager.SetCurrentMapIndex(index); GameManager.Instance.ChangeScene(SceneState.InGame); SetDummyPoolActive(false);

핵심 포인트

로비는 “인덱스”만 결정한다

로비에서 mapId나 프리팹을 직접 다루지 않습니다. 카메라가 보고 있는 FocusedMapIndex를 MapManager에 저장하면, 인게임 로딩 때 DataManager가 그 index로 mapId·MapScriptable을 다시 조회합니다.

LobbyCharacterManager 역할

캐릭터 더미의 풀링 · 표시 · 선택 확정

  • CacheDummyRefs(): CharacterManager의 캐릭터 맵을 돌며 lobbyCharacterDummy 레퍼런스를 index 순으로 정렬해 저장.
  • Show()/Hide(): 풀을 켜고 현재 인덱스 캐릭터만 활성화 (잠금 상태는 ApplyVisual로 반투명).
  • ChangeCharacter(±1): 좌우 입력 시 이전 더미 비활성화 → 새 더미 활성화.
  • SelectCurrent(): 잠금 검사 후 CharacterManager.SyncCharacterIdentity()로 현재 캐릭터를 확정.

Map handoff

CurrentMapIndex 가 전투 맵 구성을 결정

  • DataManager.GetMapData(index)로 stageCount와 enemyCountGrid 확보.
  • MapData.mapId로 MapScriptable을 조회 → mapList / bossMap / enemyIdentityList 연결.
  • 스테이지마다 ActivateRandomMap이 일반 맵 또는 보스 맵을 활성화.
Character handoff

currentCharacterName 이 플레이어 생성 · 스탯을 결정

  • 이름으로 CharacterIdentity 조회 → characterPrefab을 풀에서 인스턴스화.
  • projectilePrefab 등록 + 캐릭터 레벨 기반 스탯 적용.
  • EquipmentManager가 장비 스탯 추가 후 PlayerSpawned 이벤트 Publish.
// StageManager 진입 시퀀스 MapManager.Instance.RefreshMapData(); await MapManager.Instance.PreloadMapsAsync(); await CharacterManager.Instance.LoadAndSpawnCharacterAsync(); LoadMap(); PositionPlayer(); await SpawnEnemyAsync();

요약 — 로비는 콘텐츠 생산자가 아니라 선택 계층입니다. 매니저는 책임별로 분리되어 있어, 새 맵·캐릭터를 추가해도 SO만 등록하면 로비 UI 코드를 건드리지 않고 자동으로 더미와 선택 흐름에 편입됩니다.
